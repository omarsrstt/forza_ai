# Forza Behavioural Cloning v2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the behaviour-cloning pipeline so the trained model actually learns from images, loads correctly, and can drive the car with the intended controls.

**Architecture:** Keep ConvNeXt-Tiny (ImageNet) + LSTM. Replace 7 raw outputs with 3 physical outputs (steer `tanh`, throttle/brake `sigmoid`). Supervise every timestep densely. Hold out whole sequences for validation. Make inference replay the same rolling window the model trained on, with a per-frame CNN feature cache to hit 15 FPS on 8 GB VRAM.

**Tech Stack:** Python 3.11 (uv), PyTorch 2.6 + torchvision, Lightning 2.6, torchmetrics, pytest, numpy, Pillow, OpenCV, mss, pygame, vgamepad.

**Spec:** `docs/superpowers/specs/2026-10-25-forza-bc-design.md`

## Global Constraints

- Python env is uv-managed (`.venv`); run everything as `uv run ...`.
- GPU is an 8 GB RTX 3070 Laptop. Training must not exceed it; use AMP `16-mixed`, batch 1–2, gradient accumulation.
- Never load a checkpoint with `strict=False`. A mismatch must raise.
- Whole-sequence train/val split; a window must never span two sequences.
- Physical label ranges: steer `[-1, 1]`, throttle `[0, 1]`, brake `[0, 1]` (from pygame `[-1, 1]`, rest = -1).
- vgamepad `*_trigger_float` expects `[0, 1]` and `left_joystick_float` x expects `[-1, 1]`.
- Keep the flat file layout of the repo (modules at repo root). Do not restructure into a package.
- Existing files stay working: `record.py`, `gamepad.GamepadListener` (still records 7 values).
- Frame timing: training recorded at 15 FPS; inference paced to ~15 FPS.

## Review Focus

- **Sequence boundaries:** a training window built across a sequence boundary would inject a fake jump-cut and leak between train/val if the boundary is also the split. Expected: no window crosses a sequence.
- **Split stability:** train and eval must use the identical persisted split. Expected: both read the same `splits.json`.
- **Stale checkpoint:** loading the old 7-output checkpoint into the new 3-output model must fail loudly, not silently. Expected: loader raises with the offending keys.
- **Window warmup in `drive.py`:** for the first `k-1` steps only a partial window exists. Expected: the model is fed a correctly left-padded window (or held until full), never a malformed one.
- **Physical clamping at the gamepad boundary:** throttle/brake must be clamped to `[0,1]` and steer to `[-1,1]` before hitting vgamepad's `uint8` trigger fields. Expected: no negative/released-trigger underflow, no `>255` wrap.
